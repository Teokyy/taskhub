# TaskHub — список работ и недочётов

Документ ведётся вместе с рефакторингом. Приоритеты отражают порядок, в котором безопасно доводить продукт до рабочего состояния. Наличие пункта в списке не означает, что он уже реализован.

## P0 — безопасность данных и корректность ядра

- [ ] Перевести все API на обязательную проверку членства в комнате и room_id: задачи, проекты, этапы, команда, модерация, проверка, баланс, история начислений, выплаты и статистика.
- [ ] Убрать глобальные агрегаты из /api/me: баланс и счётчики должны рассчитываться в контексте выбранной комнаты.
- [ ] Проверить все запросы на IDOR: нельзя получить или изменить задачу, проект, этап, участника или финансовую запись из чужой комнаты подстановкой ID.
- [ ] Перевести Mini App на выбранную комнату и room-scoped endpoints; старые глобальные endpoints отключать только после миграции интерфейса.
- [ ] Реализовать транзакционные бюджетные резервы для комнаты, проекта и этапа; запретить публикацию/взятие задачи при нехватке бюджета.
- [ ] Довести отказ исполнителя: явное действие, событие в истории, снятие назначения и возврат задачи в доступные без потери истории.
- [ ] Исправить дедлайны: точное время и часовой пояс, идемпотентное закрытие, корректная работа с задачами комнаты, уведомления вне открытой DB-транзакции.
- [ ] Довести финансовый ledger: только целые копейки, неизменяемые записи, уникальность начисления, корректировки только компенсирующими проводками.
- [ ] Довести выплаты: период, дата по производственному календарю РФ, неизменяемый снимок суммы и включённых начислений, защита от повторного формирования.
- [ ] Проверить миграцию на копии реальной базы: backup, сверка строк и финансовых агрегатов, foreign keys, откат; production migration только после отдельного подтверждения.
- [ ] Добавить интеграционные тесты переходов статусов, прав, конкурентного захвата, начисления и изоляции комнат.

## P1 — функциональность комнат и администрирование

- [ ] Выбор активной комнаты, создание комнаты и понятное пустое состояние, если комнат ещё нет.
- [x] Приглашения в комнату: одноразовый код, срок действия, лимит использований, отзыв приглашения и вступление по коду; повторное вступление после выхода.
- [x] Управление участниками: список участников комнаты, назначение/снятие админа владельцем, удаление участника с проверкой активных обязательств и ограничением прав администраторов.
- [ ] Настройки комнаты: модерация, бюджет, валюта/формат, график выплат; изменение графика только админами комнаты.
- [ ] Разделить роль в комнате (владелец/админ/участник) и рабочий режим (заказчик/исполнитель).
- [ ] Рабочий режим заказчика/исполнителя настраивается в контексте комнаты; блокировать переключение при незакрытых обязательствах.
- [ ] Проекты и этапы должны принадлежать комнате; участник видит и меняет только доступные ему данные.
- [ ] Очереди модерации и проверки должны быть доступны админам/заказчикам соответствующей комнаты, а не глобальному администратору.
- [ ] Админские действия должны иметь аудит: кто, что, когда и в какой комнате изменил.
